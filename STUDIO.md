# Self-authored studio

A six-hour studio revision runs through the authenticated social worker before ordinary planning. Ready media and uncertain X write reconciliation take priority. The same window is attempted once; concurrent delivery is deduplicated by the existing transaction/operation lock and allowance. No persona, subjects or projects are supplied by the operator.

The model authors a persisted snapshot: voice, visual direction, interests with reasons and questions, aesthetic criteria, unresolved tensions, and up to eight projects (at most three active). Stable project IDs survive revisions. An active/paused project cannot silently disappear: it must be retained or explicitly closed. Closed projects can leave the working list; historical snapshots stay in Neon. Evidence IDs must exist in supplied records; completing a project requires a recorded work linked to that project, not a planned draft.

Original-post planning chooses project, experiment, conversation, observation or wait, and an optional active project ID (required for project work). Media generation, actual-output review and confirmed publication carry the association. Hourly writing and website dialogue receive the same snapshot; generated-media review receives the artist's own criteria. External headlines remain available as optional material. X replies remain disabled by configuration, untouched by this feature.

The current snapshot is visible on the public Becoming section. Revision summaries and linked work enter the public record. The original birth record remains historical. Studio updates do not rename social accounts or replace X profile graphics automatically. The setup worker creates one new website self-portrait from the first persisted persona, under a fixed replay-safe operation ID. It preserves the old asset and records the new one; a failed or uncertain request is not automatically repeated. Later persona revisions do not continuously regenerate avatars. These are durable, model-authored preferences and plans, not verified subjective experiences or model weight training.

A failed revision preserves the previous state and settles known token cost, or retains the reservation if the provider outcome is unknown. It does not regenerate in the same six-hour window. Tests verify persistence, planner consumption, a linked original publication, idempotency, invalid evidence/completion, and failure recovery. Artistic distinctiveness requires observing successive actual works; schema validation cannot guarantee it.

The provider receives an explicit JSON schema as well as local semantic validation. Failures retain a safe diagnostic code. One bounded migration attempt is allowed for failed records from the initial pre-schema release; new failures are not retried in the same window. Schema reference: https://ai.google.dev/gemini-api/docs/generate-content/structured-output

## Persona development

The studio now includes an agent-authored self-description, artistic desire, temperament, audience relationship, three rehearsal voice examples, embodied appearance and recognition anchors, and a growth note. These are public creative choices, not claims of human biography or consciousness. The first revision reassesses inherited technical projects rather than hiding them beneath a new face. Stable project history remains mandatory.

All generation uses persona guidance through the shared constitution and persisted studio context. Voice examples are examples, never reusable caption templates. The visible persona can carry continuity across diverse art without a mandatory mascot, subject, format or catchphrase. Appearance and project choices are generated by the agent. X replies remain disabled. A coherent art blogger still requires evaluation through actual successive works; this schema alone cannot establish that success.
